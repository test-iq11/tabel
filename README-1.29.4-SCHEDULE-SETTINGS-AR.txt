جدولي 1.29.4 — تنفيذ التعديلات داخل مشروع Flutter، وليس HTML

التعديلات المطلوبة:
- الشريط السفلي بالترتيب من اليمين في RTL: الرئيسية، إعداد الجدول، الجدول، الإصلاح، التقارير.
- أيقونات الشريط السفلي وأيقونات القوائم بألوان هادئة، مع الحفاظ على المظهر والجرس بالأعلى.
- «الصفوف والشعب» بطاقة مستقلة ضمن «إعداد الجدول»؛ أزيلت من داخل «إعدادات المدرسة».
- «الحصص المخصصة لكل صف» بطاقة مستقلة. الافتراضي 6 حصص/يوم لجميع الصفوف، مع إمكانية الحصة 7 للسادس يوم الأحد إذا استدعتها المتطلبات الأسبوعية وكانت هناك 7 فترات مفعلة.
- يستطيع مدير المدرسة تعديل الحد اليومي المعتاد لكل صف من 1 إلى 6؛ التغيير يُحفَظ في قاعدة البيانات لكل شعب الصف ويؤثر في القيود الحالية للخوارزمية.
- أُضيفت الفترتان السادسة والسابعة في إعدادات المدرسة الجديدة فقط. لا تُضاف الفترات تلقائياً إلى قاعدة بيانات مدرسة قديمة حتى لا تتغير أوقاتها دون إذن. تعرض البطاقة تنبيهاً لتعديل أوقات الحصص عند نقص الفترات.
- احتفظت ببطاقات المعلمين والمواد والحصص المطلوبة والتوزيع والتقارير كاملة.

ملاحظة: هذه إعدادات سعة يومية، وليست تلقائياً إنشاء مواد أو 30/31 حصة أسبوعية؛ يجب تحديد المتطلبات الأسبوعية للمواد أيضاً. الحصة السابعة للسادس تظل مشروطة بحاجة الجدول الفعلية.

كيفية التشغيل مع ZIP مضغوط:
1. ارفع jadwali-school-project-v1.29.4-schedule-settings.zip إلى جذر المستودع.
2. ضع build-jadwali-1.29.4.yml في المسار .github/workflows/build-apk.yml (أو استخدم الملف المضمن في المشروع).
3. افتح GitHub Actions وشغّل Workflow. سينفذ flutter analyze ثم اختبارات Flutter ثم يبني APK فقط عند نجاحها.
4. بعد النجاح حمّل jadwali-school-latest-release-apk من Artifacts.

التحقق المحلي: فحوص بنيوية وملفات فقط؛ لم يكن Flutter وAndroid SDK متوفرين لبناء APK أو تشغيل flutter test في هذه البيئة. لا نضمن نجاح البناء قبل تحقق GitHub Actions.
